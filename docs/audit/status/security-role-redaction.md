# Status update - technician role boundary and customer financial redaction

- **AUTH-015 (warranty access):** the technician blocklist used `/api/warranty` while the API route is `/api/warranties`, so technicians could read and mutate warranty records. Both spellings are now blocked in `src/lib/role-access.ts`, and the warranty routes require `ADMIN`/`DISPATCHER` themselves.
- **AUTH-015 (customer, vehicle, job, and search redaction):** customer list/detail responses returned invoice history, invoice counts, lifetime revenue, average ticket, and CLV to technicians; vehicle detail returned each job's quote and invoice totals; assigned-job detail returned quote/invoice line items, payments, and parts cost/markup/vendor data; and global search returned every customer, vehicle, job, and invoice. Those fields are now limited to office roles, technicians receive only the work-order view, and search is scoped to their assigned work with no invoice results.
- **AUTH-015 (destructive CRM actions):** `DELETE /api/customers/[id]` now requires `ADMIN`, `DISPATCHER`, or `SERVICE_ADVISOR`; technicians can still read and update day-to-day contact details.
- **AUTH-015 (checkout boundary):** `/api/stripe/*` is blocked for technicians, matching the existing `/api/invoices` boundary.
- **PART-011 (parts boundary):** technicians can create a bare part request and update status/notes only. Vendor, inventory, quantity, pricing, and delete actions require `ADMIN`, `DISPATCHER`, `PARTS_COORDINATOR`, `SERVICE_ADVISOR`, or `ACCOUNTANT`. The parts list is scoped to assigned jobs and strips vendor/margin fields for shop-floor roles.
- **AUTH-016 (portal and credential secrets):** customer `portalToken`, password hashes, TOTP secrets, raw and hashed reset tokens, verification tokens, session tokens, and OAuth access/refresh/ID tokens are stripped from every `apiSuccess()` response by `src/lib/api-redact.ts`. Dates and Prisma `Decimal` instances are preserved for normal JSON serialization.
- **Tests:** `src/__tests__/role-access.test.ts` covers the warranty route spellings, the technician job/settings allowlist, the checkout boundary, destructive CRM/parts roles, customer financial roles, and the customer API allowlist. `src/__tests__/api-redact.test.ts` covers nested portal-token removal and preservation of portal URLs, TOTP setup secrets, and Decimal-like values. `src/__tests__/part-visibility.test.ts` covers vendor/margin removal from shop-floor part responses.
- **Verification:** type-check, lint, 115/115 Vitest tests, and the 141-page production build pass.
